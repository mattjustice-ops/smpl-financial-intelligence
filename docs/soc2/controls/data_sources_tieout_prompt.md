### TAB 2 — ARR Waterfall

#### KPI Strip (5 cards)
| KPI | JS Source | Warehouse | Column |
|---|---|---|---|
| Ending ARR | `ARR_ACT[CLOSE_MO_IDX]` | `arr_waterfall` | `ending_arr` WHERE period=CLOSE_MONTH |
| Net New ARR | `NN_ACT[CLOSE_MO_IDX]` | `arr_waterfall` | `net_new_arr` WHERE period=CLOSE_MONTH |
| New Business | `WF_TABLE['New Business'][CLOSE_MO_IDX]` | `arr_waterfall` | `new_business_arr` WHERE period=CLOSE_MONTH |
| Expansion ARR | `WF_TABLE['Expansion'][CLOSE_MO_IDX]` | `arr_waterfall` | `expansion_arr` WHERE period=CLOSE_MONTH |
| NRR | `WF_TABLE NRR row` | `arr_waterfall` | `net_dollar_retention_rate` WHERE period=CLOSE_MONTH |

#### ARR Waterfall Table (12 cols × 7 rows)
```
JS Object: WF_TABLE
{
  Beginning:    [12 values — Jan through Dec]  → arr_waterfall.beginning_arr
  'New Business':[12 values]                   → arr_waterfall.new_business_arr
  Expansion:    [12 values]                    → arr_waterfall.expansion_arr
  Contraction:  [12 values, stored negative]   → arr_waterfall.contraction_arr
  Churn:        [12 values, stored negative]   → arr_waterfall.churn_arr
  Reactivation: [12 values]                    → arr_waterfall.reactivation_arr
  Ending:       [12 values]                    → arr_waterfall.ending_arr
}
```
Warehouse query:
```sql
SELECT period, beginning_arr, new_business_arr, expansion_arr,
       reactivation_arr, contraction_arr, churn_arr, ending_arr
FROM arr_waterfall
WHERE organization_id = $org_id
  AND period BETWEEN '2026-01' AND '2026-12'
ORDER BY period;
```
**Sign rule:** contraction_arr and churn_arr stored negative in DB.
Display as abs() in waterfall rows. net_new_arr = sum of all components.

#### Chart: `arrNN` (Bar — Net New ARR actual vs budget)
```
labels:  MO = ['Jan','Feb','Mar','Apr','May','Jun']  ← actuals only
dataset 'Actual': NN_ACT = [arr_waterfall.net_new_arr for each actual period] / 1e6
dataset 'Budget': NN_BUD = [budget.arr_new_business + budget.arr_expansion + ...] / 1e6
```
Warehouse:
```sql
-- Actuals
SELECT period, net_new_arr FROM arr_waterfall
WHERE organization_id=$org AND period <= $CLOSE_MONTH ORDER BY period;
-- Budget
SELECT period, (arr_new_business + arr_expansion + reactivation_arr
              + contraction_arr + churn_arr) AS net_new_arr
FROM budget WHERE organization_id=$org ORDER BY period;
```

#### Chart: `revARR` (Line — ARR trend actual + forecast)
```
labels:  ALL12 (Jan–Dec)
dataset 'Actual':   ARR_ACT = arr_waterfall.ending_arr for actual periods / 1e6
dataset 'Budget':   ARR_BUD = budget.arr_ending / 1e6
dataset 'Forecast': FC ARR  = arr_waterfall.ending_arr for forecast periods / 1e6
                    (same table, different periods — is_final=true for forecast)
```

#### Arrays
```
CASH_ACT [Jan–Jun]: cash_flow_statement.ending_cash / 1e6
CASH_BUD [Jan–Jun]: budget.ending_cash / 1e6
COLL     [Jan–Jun]: cash_flow_statement.cash_collections / 1e6
```
**Critical:** `CASH_ACT` values must come from `bank_account_balances` as the
authoritative source, reconciled against `cash_flow_statement.ending_cash`.
If they differ by > $1000, flag `reconciliation_gap` (`bank_timing_soft`) and use bank balance.
Do **not** call that soft gap “rounding.” Closed-actuals CFS / statement identities still fail-closed at `$1.00` (see Part 3 severity preface).

### TAB 5 — 3-Statement Model

#### Source object: `TS_DATA`
```javascript
TS_DATA = {
  Actual: {
    periods: [periods where period <= CLOSE_MONTH],
    is:  { 'YYYY-MM': { revenue, sub_rev, svc_rev, cogs, gross_profit,
                         gm_pct, sm, rd, ga, total_opex, ebitda, da,
                         interest, op_income, pretax, tax, net_income } },
    cfs: { 'YYYY-MM': { beginning_cash, net_income, da, sbc, chg_ar,
                         chg_dr, chg_ap, chg_prepaids, cfo, capex, cfi,
                         debt, cff, net_change, ending_cash } },
    bs:  { 'YYYY-MM': { cash, ar, prepaids, ppe, total_assets,
                         ap, deferred_rev, debt, total_liabilities,
                         equity, total_le } }
  },
  Forecast: {
    periods: [periods where period > CLOSE_MONTH],
    is:  { ... same fields, derived from Forecast Engine computePeriod() },
    cfs: { ... CRITICAL: beginning_cash MUST = prior period ending_cash },
    bs:  { ... }
  },
  Budget: {
    periods: ['2026-01' through '2026-12'],
    is:  { ... from budget table },
    cfs: { ... from budget table },
    bs:  { ... from budget table }
  }
}
```

#### Warehouse queries for TS_DATA:

**Actual IS:**
```sql
SELECT period,
  revenue,
  revenue * 0.967 AS sub_rev,
  revenue * 0.033 AS svc_rev,
  cost_of_revenue AS cogs,
  gross_profit,
  gross_margin_pct AS gm_pct,
  sales_and_marketing AS sm,
  research_and_development AS rd,
  general_and_administrative AS ga,
  total_opex,
  ebitda,
  depreciation_and_amortization AS da,
  interest_expense AS interest,
  (ebitda - depreciation_and_amortization) AS op_income,
  net_income AS pretax,
  0 AS tax,
  net_income
FROM income_statement
WHERE organization_id=$org AND period <= $CLOSE_MONTH ORDER BY period;
```

**Actual CFS:**
```sql
SELECT period,
  beginning_cash,
  net_income,
  depreciation_and_amortization AS da,
  stock_based_compensation AS sbc,
  change_in_accounts_receivable AS chg_ar,
  change_in_deferred_revenue AS chg_dr,
  change_in_accounts_payable AS chg_ap,
  0 AS chg_prepaids,
  net_cash_from_operating_activities AS cfo,
  capital_expenditures AS capex,
  net_cash_from_investing_activities AS cfi,
  0 AS debt,
  net_cash_from_financing_activities AS cff,
  net_change_in_cash AS net_change,
  ending_cash
FROM cash_flow_statement
WHERE organization_id=$org AND period <= $CLOSE_MONTH ORDER BY period;
```

**Forecast CFS — cash chain rule:**
```sql
-- For EACH forecast period, beginning_cash MUST equal prior period ending_cash
-- The prior period for the FIRST forecast month is the CLOSE_MONTH actual ending_cash
-- Source: cash_flow_statement WHERE period = CLOSE_MONTH (actuals)
-- NOT the forecast model's own beginning_cash assumption
```

**Budget IS/CFS:**
```sql
SELECT period, revenue, (revenue*0.967) AS sub_rev, (revenue*0.033) AS svc_rev,
  gross_profit, (gross_profit/NULLIF(revenue,0)) AS gm_pct,
  sales_and_marketing AS sm, research_and_development AS rd,
  general_and_administrative AS ga,
  (sales_and_marketing+research_and_development+general_and_administrative) AS total_opex,
  ebitda, 0 AS da, 0 AS interest, ebitda AS op_income, ebitda AS pretax, 0 AS tax, ebitda AS net_income
FROM budget WHERE organization_id=$org ORDER BY period;
```

#### `SD.monthly` object (one entry per actual period)
```javascript
SD.monthly['YYYY-MM'] = {
  reps:       <count of active quota-carrying reps>   → COUNT(quota_assignments)
  quota:      <total quota $>                         → SUM(quota_assignments.quota_amount)
  attained:   <total attained $>                      → SUM(quota_assignments.attainment_amount)
  pct:        <attained/quota>                        → computed
  bud_quota:  <budgeted quota>                        → budget.arr_new_business * 0.85 (proxy)
}
```
Warehouse:
```sql
SELECT period,
  COUNT(*) AS reps,
  SUM(quota_amount) AS quota,
  SUM(attainment_amount) AS attained,
  SUM(attainment_amount)/NULLIF(SUM(quota_amount),0) AS pct
FROM quota_assignments
WHERE organization_id=$org AND period <= $CLOSE_MONTH
GROUP BY period ORDER BY period;
```

#### `SD.pipeline` object
```javascript
SD.pipeline['YYYY-MM'] = {
  created:  <new pipeline ARR added>  → SUM(opportunities.arr_value WHERE created_date in period)
  won:      <closed won ARR>          → SUM(opportunities.arr_value WHERE stage='closed_won' AND close_date in period)
  lost:     <closed lost ARR>         → SUM(opportunities.arr_value WHERE stage='closed_lost' AND close_date in period)
  ending:   <open pipeline at period end> → SUM(opportunities.arr_value WHERE stage NOT IN closed AND as_of period_end)
  coverage: <ending / remaining_quota>    → computed
}
```

#### `SD.reps` array (individual rep data)
```javascript
SD.reps[i] = {
  id:       employees.external_id
  name:     employees.name
  role:     employees.title
  region:   employees.region  (custom field or territory table)
  ytd_q:    SUM(quota_assignments.quota_amount)     WHERE employee=rep AND period<=CLOSE_MONTH
  ytd_a:    SUM(quota_assignments.attainment_amount) WHERE employee=rep AND period<=CLOSE_MONTH
  pct:      ytd_a/ytd_q
  annual_q: quota_assignments.quota_amount (annualized)
  comm:     SUM(quota_assignments.commission_earned)
}
```

#### `SD.regions` object
```javascript
SD.regions['West'] = {

  ytd_quota:    SUM(quota_assignments.quota_amount WHERE region='West')

  ytd_pct:      computed
  jun_quota:    quota_assignments.quota_amount WHERE period=CLOSE_MONTH AND region='West'
  jun_attained: quota_assignments.attainment_amount WHERE period=CLOSE_MONTH AND region='West'
}
```

## Part 3 — Complete Tie-Out Rules

### Severity & tolerance preface (closed actuals vs soft checks)

**Closed actuals / statement identity / FE↔Board actuals cross-tie** use Matt’s bar (product fail-closed already at `$1.00` — do not loosen):

| |Δ| | Label | Gate |
|---|---|---|
| `0` | `exact` | Pass |
| `≤ $0.01` | `rounding` | Pass (cents only) |
| `$0.01 < \|Δ\| ≤ $1.00` | `investigate` | Weird — investigate; product hard-fail is **> $1** |
| `> $1.00` | `significant_miss` / `data_mismatch` | **FAIL** — not rounding. Multi-thousand = significant miss |

See [reconcile_financial_statements.md](./reconcile_financial_statements.md) for June 2026 FE↔Board deltas labeled honestly.

**Soft checks (do not call these “rounding” for statement actuals):**

| Check type | Typical band | Label |
|---|---|---|
| Bank balance vs CFS ending cash | Soft flag ~`$1,000` timing | `bank_timing_soft` / `reconciliation_gap` |
| Million-scale **display** arrays (`/ 1e6`) | Display precision ~`$0.001M` | `display_precision` — not statement rounding |

Default `TOL_ACTUALS = 1.00` for closed-actuals statement rules below. Older `$100` / `$1K` “rounding” wording for actuals identities is **retired**.

### Rule Set A — ARR Tie-Outs (Must hold at every close)

**A1 — ARR chain integrity (month-over-month):**
```
For every period N and N+1:
  arr_waterfall.ending_arr[N] == arr_waterfall.beginning_arr[N+1]
  tolerance: $0 (exact)
```

**A2 — ARR waterfall components sum to net new:**
```
new_business_arr + expansion_arr + reactivation_arr
+ contraction_arr + churn_arr == net_new_arr
tolerance: $1.00 (closed actuals — TOL_ACTUALS; |Δ|≤$0.01 = rounding label only)
Where contraction_arr and churn_arr are NEGATIVE values
```

**A3 — ARR ending ties from beginning:**
```
beginning_arr + net_new_arr == ending_arr
tolerance: $1.00 (TOL_ACTUALS)
```

**A4 — Board Platform WF_TABLE ties to warehouse:**
```
WF_TABLE['Beginning'][MONTH_IDX] == arr_waterfall.beginning_arr[period] / 1 (raw $)
WF_TABLE['Ending'][MONTH_IDX]    == arr_waterfall.ending_arr[period] / 1
tolerance: $1.00 (TOL_ACTUALS for closed actuals)
```

**A5 — Forecast Engine SRC.actuals ties to warehouse:**
```
SRC.actuals[period].arr_eop == arr_waterfall.ending_arr[period]
SRC.actuals[period].arr_nn  == arr_waterfall.net_new_arr[period]
tolerance: $1.00 (TOL_ACTUALS)
```

**A6 — Forecast BOP chain (first FC period):**
```
SRC.actuals[CLOSE_MONTH].arr_eop
  == computePeriod(FC_P[0]).arr.arr_bop
  == TS_DATA.Forecast.is[FC_P[0]] derived BOP
tolerance: $1.00 (TOL_ACTUALS)
```

### Rule Set B — Cash Tie-Outs

**B1 — Cash chain (most critical):**
```
For every period N and N+1:
  cash_flow_statement.ending_cash[N] == cash_flow_statement.beginning_cash[N+1]
  tolerance: $1.00 (TOL_ACTUALS — not $100 “rounding”)
```

**B2 — Cash vs bank reconciliation (soft check — bank timing, not statement rounding):**
```
cash_flow_statement.ending_cash[CLOSE_MONTH]
  == bank_account_balances.ending_balance[last day of CLOSE_MONTH]
  soft flag: $1000 (bank_timing_soft — timing differences allowed, flagged if exceeded)
  IF gap > $1000: store in cash_flow_statement.reconciliation_gap, use bank_balance as truth
  Do NOT label bank gaps as “rounding.” Statement CFS identity still uses TOL_ACTUALS = $1.00.
```

**B3 — Forecast Engine seed ties to actual:**
```
SRC.actuals[CLOSE_MONTH].ending_cash
  == compute() seed value `cash`
  == computePeriod(FC_P[0]).cfs.beg_cash
  == TS_DATA.Forecast.cfs[FC_P[0]].beginning_cash
tolerance: $1.00 (TOL_ACTUALS)
Any gap here BREAKS all downstream cash metrics. Block publish if fails.
```

**B4 — Board Platform CASH_ACT ties to warehouse (display precision):**
```
CASH_ACT[MONTH_IDX] == cash_flow_statement.ending_cash[period] / 1e6
tolerance: $0.001M display_precision (≈ $1K on million-scale UI only — not “rounding” for statement actuals)
Underlying statement / FE↔Board cash still fail-closed at $1.00.
```

**B5 — CFO identity (closed actuals):**
```
cash_flow_statement.net_cash_from_operating_activities[period]
  == (net_income + da + sbc + chg_ar + chg_dr + chg_ap + chg_prepaids)
tolerance: $1.00 (TOL_ACTUALS — multi-thousand gaps are significant_miss, not rounding)
```

## Part 4 — The `runTieOut()` Function (Implement This)

This function runs automatically after every data load and every publish.
Returns `{ passed: boolean, failures: string[] }`.
**Publish is BLOCKED if `passed === false`.**

Closed-actuals / statement identities use `TOL_ACTUALS = 1.00` (product fail-closed). Soft bank/display checks are separate — see Part 3 preface.

```javascript
function runTieOut(srcActuals, tsData, engineResults, closeMonth) {
  const TOL_ACTUALS = 1.00; // closed actuals — fail if |Δ| > $1 (Matt bar)
  const TOL_EXACT = 0; // for integer counts
  // Soft checks (not “rounding”): bank timing ~$1000; display /1e6 ~$0.001M
  const fails = [];
  const FCp   = Object.keys(tsData.Forecast.is || {}).sort();
  const ACTp  = Object.keys(srcActuals).sort();

  // ── Rule A: ARR ──────────────────────────────────────────────────────
  ACTp.forEach(p => {
    const aw = srcActuals[p];
    // A2: components sum
    const comp_nn = aw.arr_nb + aw.arr_exp + aw.arr_react + aw.arr_cont + aw.arr_churn;
    chk('A2', p, 'arr net_new components', comp_nn, aw.arr_nn, fails, TOL_ACTUALS);
    // A3: ending = beginning + net_new
    chk('A3', p, 'arr ending=bop+nn', aw.arr_bop + aw.arr_nn, aw.arr_eop, fails, TOL_ACTUALS);
  });

  // A6: forecast BOP chain
  if (FCp.length > 0) {
    const firstFC = FCp[0];
    const actEnd  = srcActuals[closeMonth]?.arr_eop;
    const fcBOP   = engineResults?.[firstFC]?.arr?.arr_bop;
    chk('A6', firstFC, 'forecast arr_bop == actual arr_eop', actEnd, fcBOP, fails, TOL_ACTUALS);
  }

  // ── Rule B: Cash ─────────────────────────────────────────────────────
  // B3: forecast cash seed
  if (FCp.length > 0) {
    const firstFC    = FCp[0];
    const actEndCash = srcActuals[closeMonth]?.ending_cash;
    const fcBegCash  = tsData.Forecast.cfs?.[firstFC]?.beginning_cash;
    const engBegCash = engineResults?.[firstFC]?.cfs?.beg_cash;
    chk('B3a', firstFC, 'TS_DATA forecast beg_cash == actual ending', actEndCash, fcBegCash, fails, TOL_ACTUALS);
    chk('B3b', firstFC, 'Engine forecast beg_cash == actual ending', actEndCash, engBegCash, fails, TOL_ACTUALS);
  }

  // ── Rule C: IS ───────────────────────────────────────────────────────
  ACTp.forEach(p => {
    const is = tsData.Actual?.is?.[p];
    if (!is) { fails.push(`C: TS_DATA.Actual.is missing period ${p}`); return; }
    const s  = srcActuals[p];
    chk('C3a', p, 'REV_ACT', s.revenue, is.revenue, fails, TOL_ACTUALS);
    chk('C3b', p, 'GP_ACT',  s.gross_profit, is.gross_profit, fails, TOL_ACTUALS);
    chk('C3c', p, 'EBITDA',  s.ebitda, is.ebitda, fails, TOL_ACTUALS);
  });

  // ── Rule F: Cross-tie engine ↔ board ────────────────────────────────
  FCp.forEach(p => {
    const eng = engineResults?.[p];
    const ts  = { is: tsData.Forecast.is?.[p], cfs: tsData.Forecast.cfs?.[p] };
    if (!eng || !ts.is) { fails.push(`F: missing data for ${p}`); return; }
    chk('F2', p, 'revenue',       eng.is.revenue,      ts.is.revenue,           fails, TOL_ACTUALS);
    chk('F3', p, 'ebitda',        eng.is.ebitda,        ts.is.ebitda,            fails, TOL_ACTUALS);
    chk('F4a',p, 'beg_cash',      eng.cfs.beg_cash,     ts.cfs?.beginning_cash,  fails, TOL_ACTUALS);
    chk('F4b',p, 'end_cash',      eng.cfs.end_cash,     ts.cfs?.ending_cash,     fails, TOL_ACTUALS);
  });

  const passed = fails.length === 0;
  if (passed) console.log('✓ TIE-OUT PASSED');
  else { console.error(`✗ TIE-OUT FAILED (${fails.length} issues)`); fails.forEach(f=>console.error(' '+f)); }
  return { passed, failures: fails };
}

function chk(rule, period, metric, expected, actual, fails, tol) {
  if (actual === undefined || actual === null) {
    fails.push(`[${rule}] ${period} ${metric}: missing`); return;
  }
  const diff = Math.abs((expected||0)-(actual||0));
  if (diff > tol) {
    fails.push(`[${rule}] ${period} ${metric}: expected=${expected?.toFixed(0)} actual=${actual?.toFixed(0)} diff=${diff.toFixed(0)}`);
  }
}
```
